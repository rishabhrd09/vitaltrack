CORS: wildcard without credentials

Browser refresh uses a host-only HttpOnly cookie. Hosted environments use Secure and SameSite=Strict and limit the cookie path to the web-auth endpoints. A native Android request supplies a bearer token explicitly. A browser also uses bearer access tokens for inventory, but its refresh credential can be attached automatically by the browser.

Enabling browser login requires an explicit WEB_APP_ORIGINS list included in CORS_ORIGINS. The cookie endpoint checks the exact Origin and X-CareKosh-Web marker and rejects cross-site fetch metadata. CORS controls browser access across origins. It cannot establish ownership of an inventory item. Server-side authorization still runs on every protected operation.

Minting a token pair

{{x:B/app/core/security.py:137-159}}
  • The access token carries session_version as an extra claim; the refresh token carries it plus a jti.
  • expires_in is reported in seconds (1800 by default) so clients can plan refreshes.
  • Signing uses settings.secret_key_value with JWT_ALGORITHM (HS256); decoding passes algorithms=[…] as an allow-list, which blocks algorithm-confusion attacks.

Partial updates: omitted versus null

{{x:B/app/api/v1/items.py:432-463}}
  • Optional columns are written only if the client sent the field (model_fields_set), so "notes": null clears notes while an omitted notes leaves them alone.
  • Required columns treat None as "not sent" and are never set to NULL.
  • Nothing is assigned to the ORM object: the values go into one conditional UPDATE, so the version check and the write are a single statement.

Order status changes: claim the old state

{{x:B/app/api/v1/orders.py:338-352}}
  • The transition was validated against the status read earlier; the UPDATE only fires while the row still has that status.
  • Zero rows means another request moved the order first, so the API answers 409 instead of applying a stale transition (no lost update, no last-writer-wins).

Applying stock exactly once

{{x:B/app/api/v1/orders.py:465-488}}
  • The claim moves the order from received to stock_updated. Two concurrent applies cannot both claim it.
  • Stock updates follow in the same transaction; if any fails, get_db rolls back the claim and every stock change together.

Refresh-token rotation

{{x:B/app/api/v1/auth.py:781-831}}
  • The user row is locked first, then the refresh row is claimed: the same lock order as password changes, so a token cannot slip past a password change.
  • The claim is one conditional UPDATE; only one concurrent request can flip is_revoked.
  • The new refresh token gets a new jti and a new 30-day expiry.

AI concurrency: one billable call per kind per account

{{x:B/app/services/ai_guard.py:232-256}}
  • "Active" means a reserved row that has not expired. The checks run under the global advisory lock, so the count cannot change between the check and the insert.
  • A person can have a question interpreted while an earlier answer is still being spoken (different kinds), but cannot queue two billable calls of one kind.

Refuse before reading the body

{{x:B/app/services/ai_body_limit.py:62-90}}
  • Pure ASGI middleware sees the raw scope: path, method and headers, before any body bytes are read.
  • An AI upload missing a bearer header gets 401 before the middleware buffers the body. The authentication dependency validates the token later, with the security headers that the inner middleware would otherwise add.

Encrypting a personal provider key

{{x:B/app/services/sarvam_credentials.py:51-79}}
  • The envelope binds the ciphertext to its owner and provider: copying a ciphertext into another user's row would fail the owner check.
  • raise … from None hides why decryption failed (bad key, tampered token, wrong owner) from the caller.

A production configuration guard

{{x:B/app/core/config.py:240-249}}
  • Email links are built from FRONTEND_URL. Production refuses to start without it, rather than sending links to 127.0.0.1.
  • Validation at start-up turns a silent misconfiguration into a failed deploy that keeps the old instance serving.
