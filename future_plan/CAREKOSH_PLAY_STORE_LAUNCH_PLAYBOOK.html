Device smoke checklist

  • Register, verify, login, refresh after expiry, recover password and log back in after old sessions are invalidated.
  • Edit profile without changing the read-only email; exercise all existing navigation/buttons.
  • Create/edit categories and items; check stock values and stale-version conflicts. 7 Oct 2026: the app has no stock +/− control — quantities change through Edit Item or by applying a received order. 8 Oct follow-up: A-1 is fixed locally; Edit Item retains the opening version, so a cache refetch cannot bypass a stale-save conflict. Repeat the two-device scenario before release.
  • Create, receive and apply an order once; verify last-ordered items and stock. Confirm retries do not accidentally create a second order; create retry deduplication remains deferred. 7 Oct 2026: on the feature branch deduplication exists — the app sends one localId per Save press, Retry reuses it, and migration 0010 makes the server return the existing order. The order screen offers only pending → received and received → “Update Stock”; “Remove” appears for every status but the server deletes only pending/declined orders (others return 400), and partially received orders display as “Unknown”.
  • Load older history, including more than 100 orders; export order and inventory PDFs.
  • Test network loss, recovery, shared-device logout/login, and cache privacy.
  • Test deletion only with a disposable account; opening the confirmation link must not delete until the form is submitted. 7 Oct 2026: the app has no change-password or cancel-deletion screen; exercise those flows through the API.
  • 7 Oct 2026, voice build only: download and remove the speech pack, grant and deny the microphone permission, record and review a transcript, ask offline (expect “Last known”), enable and withdraw Groq understanding, and check spoken replies with and without an offline Android voice installed.

After release and rollback

Check both process liveness and sustained database readiness, auth failures, order errors, connection/lock pressure and support reports. Verify alert delivery and recovery procedures. A Starter plan in render.yaml is configuration intent, not proof of actual uptime or deployed plan.

Backend rollback requires schema/session/counter compatibility. Migration 0007 refuses automatic downgrade; no casual downgrade or delete-users cleanup is part of this release.
